# Master tags and feature access

Jobs Profile adds a third onboarding/profile-creation type. Master also has an exclusive **Job Seeker** option under Allowed features and role-controlled Job Seeker sections. It is not an assignable tag. Apply `supabase/jobs-profile-home.sql` after all migrations below; see [Jobs Profile and Job Seeker mode](jobs-profile-home.md).

Superadmin → Master creates tags, lists definitions and edits feature permissions. Profiles retains tag assignment and account support, and creates administrator profiles.

Individual and Organisation are chosen during first-time profile setup. Workspace deployments use the existing workspace choice; deployments without workspaces save the account profile type. Users see one choice, and neither type is an assignable tag. University, Hospital, Contributors, Standard, Founders, Special, Hero, God, Fraud, Scammer, Narration Setter, Gov-Departments, Commercial/Enterprises, Community and Manufacturer are independent tags. The existing Private profile tag remains available. Master uses a flat list and opens creation/editing in a popup without parent or built-in labels. Every tag's visibility is editable: Public displays the label, Internal hides the label, and Private hides the assigned profile and knowledge from public visitors. Built-in tag names and keys remain fixed. Changing visibility preserves its permissions.

The seven permissions cover profile/public page editing, content/files/activity, AI knowledge/visitor Q&A, Store/orders/payments, enquiries, invites/suggestions and jobs. Each assigned tag must allow a feature. Untagged accounts follow Standard. Defaults retain existing Studio access; Superadmin can restrict any role. Account settings and platform support remain available to profile administrators. Contributors can add their own files and articles, without settings or private profile information. Profile type selection does not grant feature permissions.

Every signed-in request reloads current role permissions from the database. UI navigation refreshes on window focus. Workspace membership roles and tag permissions must both allow an action. Website connections and source access policies require knowledge permission; team tools require community permission. The Studio assistant, combined analytics, webhooks and data exports require all feature permissions because they access multiple areas. Workspace selection remains accessible. Shared page writes separately enforce Store and activity permissions; content-only accounts use a limited activity API. Delivery assets require Store access.

Internal staff tags receive specific platform capabilities independently of Studio features. `profiles.create` opens profile creation, `profiles.edit` allows editing ordinary profiles and assigning non-privileged tags, and `master.manage` opens tag and feature-permission management. Full Superadmin selects these in a tag's permission popup or a profile's edit popup. Staff navigation and API access use their current database grants; a tag's internal visibility does not remove its permissions. Only full Superadmin can grant platform capabilities or approve profiles. The Profile Creator tag remains create-only by default. Internal tag labels and definitions are removed from public responses. See [Jobs and profile creation](jobs-profiles.md) for installation and approval details.

For an existing database, run `supabase/master-rbac.sql` after `admin-experience.sql`, followed by the workspace prerequisites, `supabase/jobs-profiles.sql`, `supabase/staff-permissions.sql` and `supabase/tag-visibility.sql` before releasing this application. It preserves assignments and privacy, and reruns preserve edited permissions. An existing custom tag with a newly reserved name receives a unique `(custom)` suffix; its key, assigned accounts and access rules remain unchanged. Reapply the latest migrations last if running older migrations again.

Validation: `npm test`, `npm run build`. Browser fixture: `npm run dev:web` then `/tests/browser/governance.html?role=owner&view=/superadmin/master`.
